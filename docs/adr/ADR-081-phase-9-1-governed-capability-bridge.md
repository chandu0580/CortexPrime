# ADR-081 — Phase 9.1: Governed Capability Bridge & Kubernetes READ Contract

Status: Accepted · Date: 2026-08-12 · Phase 9.1 · Follows ADR-080 (Phase 9.0 discovery) and the Phase 5/6 governance ADRs

## Context

Phase 9.0 found that CortexPrime's governed capability surface is tiny, that Kubernetes exists only as a V1 read-only connector (not a governed `ProviderOperationSpec`), that Kubernetes WATCH is blocked (the V1 connector strips `resourceVersion`), and — critically — that the risk/reversibility/verification/autonomy semantics already exist on the Phase-8 intelligence plane but are **decoupled** from the governed connectivity `CapabilityContract`. Phase 9.1 makes Kubernetes the *first real governed capability* by **bridging** those two planes and declaring a read-only Kubernetes catalog — without a second capability model, gateway, executor, scheduler, credential system, or provider path.

## Decision

**1. The capability bridge is a reference contract, not a new model (Part B).** `CapabilityProfile` binds one governed operation to its Phase-8 semantics by REUSE: it carries an existing `RiskClassification`, an `AutonomyLevel` ceiling, a `VerificationRequirement`, `resource_scope`, reversibility, `EffectSemantics`, timeout, and `policy_version`, and it `.to_capability()`-bridges to the exact Phase-8 `Capability` the `AutonomyPolicy` (8.8) already consumes. It keeps the four concepts distinct — capability ≠ permission ≠ authorization ≠ autonomy — and duplicates none of the risk/autonomy types.

**2. The read-only guarantee is a construction-time invariant (Part D).** `CapabilityProfile.__post_init__` refuses a READ profile whose autonomy ceiling exceeds A1 or that requires verification, and refuses a mutating profile that requires no verification. "A read is never an autonomous action; a write is never unverifiable" is enforced by the type, not a convention.

**3. Kubernetes becomes a governed capability, not a connector (Part C/E).** A declared, immutable `kubernetes_read_catalog()` of six `ProviderOperationSpec`s models the Kubernetes HTTP API (`GET /api/v1/.../pods`, `.../deployments`, `.../events`, `.../log`) — the smallest read set for the first incident vertical (CrashLoopBackOff / deployment failure). Every op is READ / READ_ONLY. The module imports no `kubernetes` SDK, no `httpx`, no `backend.connectors` (V1), and no credential carrier — structurally fenced by the existing `BND-PROVIDER-SDK` / `BND-DIRECT-HTTP` / `BND-AMBIENT-CREDENTIALS`. Provider I/O happens ONLY when the governed execution transport invokes the composed adapter; there is no second gateway/executor/scheduler/credential/provider.

**4. resourceVersion is preserved as a normalized top-level evidence field (Part F).** The governed `evidence()` extraction is deliberately bounded to top-level scalars (ADR-042), so the adapter NORMALIZES a Kubernetes response — lifting `metadata.resourceVersion` to a top-level `resourceVersion` — and every LIST/GET spec keeps `resourceVersion` in its `response_evidence_fields` (and requires it). A governed read's resourceVersion therefore survives into the Observation, establishing the data contract a future LIST→WATCH continuity (9.2/9.3) needs. resourceVersion is never fabricated; the log op (no envelope) legitimately omits it. **WATCH is NOT implemented (Part S).**

**5. Reuse the existing observation/world/authorization path exactly (Part G/H/I).** A governed read → `ReadObservation` (Phase 7.2) → `cw_observation` → `Fact` → `WorldQuery`, provider-neutral (no Kubernetes-specific world tables/facts/queries). The adapter never inserts into `cw_observation`; the World Plane owns ingestion. Authorization is the existing chain (wrong tenant / missing capability / invalid scope / expired / unknown operation all refuse, with no provider call). Tenant is mandatory and exercised through the durable path.

**6. The scripted provider is honestly labeled (Part K/O).** No real cluster or credential is available (Phase 5.5 class), so the real HTTPS-to-API-server adapter is DEFERRED. A scripted `TestProviderAdapter` composes the REAL catalog and answers with normalized K8s bodies (carrying resourceVersion) — proving the governed capability path and the resourceVersion data contract without contacting a cluster. Kubernetes auth via `KUBECONFIG`/in-cluster is an allowed ambient-infra path (excluded from `BND-AMBIENT-CREDENTIALS`); the Phase 5.5 credential blocker is untouched, and no credential is manufactured or inspected.

**7. No new fitness rule (Part N).** The read-only invariant is enforced by the `CapabilityProfile` contract + the effect gate + a unit test on the catalog; the no-SDK / no-httpx / no-ambient-credential invariants by the existing `BND-PROVIDER-SDK` / `BND-DIRECT-HTTP` / `BND-AMBIENT-CREDENTIALS` (the gate passing over 1173 modules confirms the governed K8s module imports nothing forbidden). Adding a Kubernetes-specific read-only rule would duplicate the contract+test+gate guarantee — a cosmetic rule, which Part N forbids.

## Consequences

Kubernetes is a governed capability of CortexPrime: a read runs through the ONE action path, becomes a durable Observation preserving resourceVersion, a Fact, and a WorldQuery answer — proven against real Postgres with a scripted provider (real cluster deferred), read-only by construction, crash-safe, replay-inert, tenant-scoped. The bridge lets the Phase-8 `AutonomyPolicy` evaluate a real governed capability. This unblocks 9.2 (governed K8s reads against a real cluster), 9.3 (WATCH on the preserved resourceVersion), and the read-only incident investigator (9.5). No second authority of any kind was created. L1–L16, One Plane of Action, World immutability, independent Assurance, tenant isolation, the secret firewall, and the Phase 5.5 credential blocker remain intact and untouched. WATCH and any write capability are explicitly NOT introduced.
