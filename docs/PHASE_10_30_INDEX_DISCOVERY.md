## Ownership Model `[VERIFIED from ADR-109, ADR-114, the lineage, and the databases]`

1. **The migration lineage owns the schema, indexes included** (ADR-109: Alembic is the canonical owner; production refuses `create_all`). Every database on the instance carries exactly the migrations' indexes (fresh == head), so the deployed truth and the owner agree; the ORM is the only dissenting party, and it has dissented since the day each model was written.
2. **ORM metadata mirrors the owner.** ADR-114 set the precedent on `cost_tracking`: the model was aligned to the lineage — migrated indexes declared *by their migrated names*, unmigrated `index=True` markers removed, nothing created because the model wished it. This phase applies the same rule to the remaining 27 tables.
3. **PostgreSQL-specific indexes are migration-owned and mirrored exactly in the ORM so autogenerate cannot propose dropping them.** ADR-114's stated next step was to "protect the expression indexes"; suppression is forbidden, so the only protection is a faithful ORM representation. Empirically (§8), Alembic 1.14 emits no operation when the ivfflat indexes are declared as column indexes with `postgresql_ops` + `postgresql_with` and the GIN indexes with the reflected expression text. The database is not touched.
4. **Runtime index creation:** the application creates indexes only in Neo4j (`backend/infrastructure/neo4j/schema.py`, `enterprise_graph_service.py`); never in PostgreSQL.

- 12 unique cases are UNIQUE **indexes** in the database (`create_index(..., unique=True)` in 0007/0001) and `unique=True, index=True` in the ORM (SQLAlchemy renders that as a unique *index*, not a constraint) — same semantics, different names → F. Mirrored as `Index(name, col, unique=True)`.
