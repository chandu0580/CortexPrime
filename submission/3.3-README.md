## What this project does

CortexPrime monitors a software system, detects real production problems,
explains the root cause with evidence, and proposes or applies a fix — with
every risky action gated behind human approval.

It ships with **10 working detectors** (deploy regression, container health,
credential expiry, vulnerability scanning, cost anomalies, and others). Each
follows the same loop:

> **detect → explain the cause → file a ticket → request approval → execute the fix → verify**

## Before you begin

Install the software listed in **3.1 — Supporting Software**. At minimum you
need:

- Python 3.13+
- Node.js 20+
- Docker Desktop (running)

Check they are installed:

```bash
python --version     # expect 3.13 or higher
node --version       # expect v20 or higher
docker --version     # expect 24 or higher
```

# PART 1 — Setup (first time only)

### Step 1 — Open a terminal in the project folder

```bash
cd cortexprime
```

### Step 2 — Create a Python virtual environment

A virtual environment keeps this project's packages separate from your system.

**Windows:**
```bash
python -m venv .venv
.venv\Scripts\activate
```

**macOS / Linux:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

You will see `(.venv)` at the start of your terminal prompt when it is active.

### Step 3 — Install the Python packages

```bash
pip install -r requirements.txt
```

This installs 62 packages and takes 3–5 minutes.

### Step 4 — Install the frontend packages

```bash
cd frontend
npm install
cd ..
```

### Step 5 — Create the configuration file

Copy the example configuration to a real one:

**Windows:**
```bash
copy .env.example .env
```

**macOS / Linux:**
```bash
cp .env.example .env
```

### Step 6 — Fill in the required settings

Open `.env` in a text editor. You must set these five values:

| Setting | What to put |
|---|---|
| `JWT_SECRET_KEY` | Any random string, **at least 32 characters** |
| `JWT_REFRESH_SECRET` | A different random string, at least 32 characters |
| `CORTEX_USER` | The login username you want, e.g. `admin` |
| `CORTEX_PASSWORD_HASH` | See Step 7 below |
| `POSTGRES_PASSWORD` | Any password for the database |

To generate a random secret:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

### Step 7 — Generate the login password

Passwords are stored as a bcrypt hash, never as plain text. Run this command,
replacing `YourPassword` with the password you want:

```bash
python -c "import bcrypt; print(bcrypt.hashpw(b'YourPassword', bcrypt.gensalt()).decode())"
```

Copy the output (it starts with `$2b$`) into `CORTEX_PASSWORD_HASH` in `.env`.

### Step 8 — Start the database and backing services

```bash
docker compose up -d cortex-postgres cortex-redis
```

Wait about 20 seconds for PostgreSQL to finish starting, then confirm both are
running:

```bash
docker ps
```

You should see `cortex-postgres` and `cortex-redis` listed.

### Step 9 — Create the database tables

```bash
alembic -c backend/database/migrations/alembic.ini upgrade head
```

This applies all 11 schema migrations. You only do this once — and again later
if the schema changes.

**Setup is now complete.**

# PART 2 — Running the project

You need **two terminals** open at the same time — one for the backend, one for
the frontend.

### Step 10 — Terminal 1: start the backend

```bash
cd cortexprime
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # macOS / Linux

uvicorn backend.main:app --reload --port 8000
```

Wait until you see:

```
Application startup complete.
Uvicorn running on http://127.0.0.1:8000
```

Leave this terminal open and running.

### Step 11 — Terminal 2: start the frontend

Open a **second** terminal:

```bash
cd cortexprime/frontend
npm run dev
```

Wait until you see:

```
Ready in ... ms
Local: http://localhost:3000
```

Leave this terminal open too.

### Step 12 — Open the application

Open a web browser and go to:

```
http://localhost:3000
```

### Step 13 — Log in

Enter the username from `CORTEX_USER` and the password you chose in Step 7.

You will land on the **Executive Dashboard**, which shows all ten detector
panels.

|---|---|---|
| 1 | Open the **Executive Dashboard** | Ten detector panels, each showing current status |

### Demonstrating a real detection (optional)

To see the container-health detector fire, deliberately create a crash-looping
container:

```bash
docker run -d --name crashtest --restart=unless-stopped alpine sh -c "exit 1"
```

Wait about 60 seconds, then open the Docker Health panel — the container will be
flagged as crash-looping.

Clean up afterwards:

```bash
docker rm -f crashtest
```

# PART 4 — Stopping the project

1. Press `Ctrl + C` in the frontend terminal
2. Press `Ctrl + C` in the backend terminal
3. Stop the database services:

```bash
docker compose down
```

Your data is preserved. To start again, repeat **Steps 8, 10, 11** only —
setup does not need repeating.

# PART 6 — Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| `ModuleNotFoundError` | Virtual environment not active | Re-run the `activate` command from Step 2 |
| `JWT_SECRET_KEY is required` | Missing or too short | Must be 32+ characters in `.env` |
| `connection refused` on port 5432 | PostgreSQL not started | Run Step 8, wait 20 seconds |
| Login always fails | Password hash wrong | Regenerate with Step 7; the value must start with `$2b$` |
| Port 8000 already in use | Another program is using it | Use `--port 8001` and update `NEXT_PUBLIC_API_URL` in `.env` |
| Port 3000 already in use | Another program is using it | Run `npm run dev -- -p 3001` |
| Frontend loads but shows no data | Backend not running | Check Terminal 1 is still running |
| Docker panel is empty | Docker Desktop not running | Start Docker Desktop and wait for it to be ready |
